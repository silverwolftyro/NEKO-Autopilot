## C1 · Demo 场景设计

**在哪**：蒙德城野外，视野里能看见 1~3 个丘丘人
**做什么**：站着不动，让引擎自己跑
**YUI 说什么**：检测到敌人时按 `ENEMY_DETECTED` 播报（这是真机跑过 20 次的事件码）
**证据强度**：✅ 全部环节都有真机记录

**前置**：
- [ ] `world_attack_only_with_enemy` 规则 `enabled = true`（**当前就是开的** ✅）
- [ ] 引擎能拿到 DirectML（CPU 路线会因超时被整个关掉，见 `ENTITY_DETECTOR_UNAVAILABLE`）

**预期现象**：角色自己转身、平A。宠物偶尔冒泡。

### 场景 B · 开关菜单触发播报（最稳、最能说明「感知」）

**在哪**：任意大世界画面
**做什么**：按 `B` 打开背包，再按 `B` 关掉
**YUI 说什么**：场景切换事件（`SCENE_CHANGED`，真机 24 次）
**证据强度**：✅ 场景判定真机验证过

**预期现象**：**什么都不会发生**才对 —— 场景检测只是二值的
（WORLD / UNKNOWN），菜单打开时**不按任何键**。
这条恰恰用来证明「它知道自己看不清了就不乱动」。

## C1.5 · 如果当天**就是**要演寻路（附条件）

> ⚠️ 这一节的前提是：**你已经按下面第 1 条在 T-1 天真机跑通过至少一次。**
> 没跑过就直接上台，等于把整个 demo 押在一个从未执行过的链路上。

**第 0 条纪律不变**：演之前先确认引擎**没在跑**。两者抢同一套键鼠注入，
Console 会在启动前直接拒绝（这是设计，不是 bug）。

### T-1 天必须做的（按顺序）

0. **（不需要原神，先做）用假脚本把 Console 寻路 UI 走一遍** ——
   `autopilot/tools/fake_pathfind.py` 复刻了真脚本的参数、状态文件、
   停止协议，不碰游戏。把 `config.toml` 的 `engine.pathfind_script` 指向它，
   Console 里点「启动 / 停止」，确认按钮不灰、状态在跳、停止有提示。
   完整说明见 `console_pathfind_offline_test.md`。

   ⚠️ **这一步过了不代表能演寻路** —— 它只证明 Console 的管道通，
     不证明真脚本能把角色带到终点。真要演，下面第 1 条才是准入条件。

1. **真机跑通一次 DIRECT 模式**。这是唯一的准入条件：
   - 启 Console（提权）→ 「寻路」页签
   - 地图上点一个**离当前位置 10~20 米**的起点和终点
     （⚠️ 点选精度 ≈ **±9 米**，点太近会没有位移；详见
     `navigation_interface.md` §二）
   - 起点来源选「手动输入」或「从地图选点」均可
   - 点「启动寻路」→ **确认角色真的动了**

2. **确认三个「别承诺」的点没被误当成「能用」**：
   - 起点来源里的「截图识别」「定位服务」是**置灰的**，点了会说明为什么
   - 目标描述框只认**传送点地名**或**坐标**；「七天神像-风」这种同名地会
     明确告诉你「有 6 个同名地点」而不是随便挑一个
   - 导航模式的「自动规划」是**预留**，选了会抛异常

3. **验证停止语义**（这条最容易被忽略，也最难看）：
   - 点「停止寻路」→ 正常应显示「已停止（flag 生效，脚本自己退的）」
   - 若显示「已 terminate 兜底（★按键状态可能不明）」→
     **角色可能还在走**，演示前按一下空格或点一下游戏恢复
   - 出现兜底就说明脚本没接住停止信号，**当天别演这条**

### 当天现场

- **不要**演 WAYPOINTS 模式（要事先裁路点文件，当天来不及）

## C2 · 一键启动脚本

### `start_demo.bat`

放在 `<WORKSPACE_ROOT>\demo\start_demo.bat`（**2026-10-13 已落盘并逐路径核实**）。

**不打开原神也能跑到第 3 步之前** —— 前两步与游戏无关，
只有引擎需要游戏窗口才不报错。

```bat
@echo off
setlocal
chcp 65001 >nul
title N.E.K.O Demo Launcher

set "REPO=<REPO_ROOT>"
set "PLUGIN=%REPO%\plugin\plugins\genshin_game_buddy"
set "PY=%REPO%\.venv\Scripts\python.exe"
set "CONSOLE_DIR=<CONSOLE_ROOT>"
set "CPY=%CONSOLE_DIR%\.venv\Scripts\python.exe"

echo ============================================================
echo   N.E.K.O Demo Launcher
echo   按顺序启动：宿主 -^> 主控台 -^> 引擎 -^> 悬浮卡片
echo ============================================================
echo.

where "%PY%" >nul 2>nul
if errorlevel 1 (
    echo [X] 找不到引擎 Python：%PY%
    echo     先检查仓库路径，或改这个脚本里的 REPO 变量。
    pause & exit /b 1
)
where "%CPY%" >nul 2>nul
if errorlevel 1 (
    echo [X] 找不到 Console Python：%CPY%
    pause & exit /b 1
)
echo [OK] Python 路径就绪
echo.

echo [1/4] 启动 N.E.K.O 宿主...
start "N.E.K.O" cmd /k "cd /d "%REPO%" && "%PY%" launcher.py"
timeout /t 12 /nobreak >nul
echo       等 12 秒给宿主加载插件
echo.

echo [2/4] 启动主控台 Console（会弹 UAC，点「是」）...
start "Console" cmd /k "cd /d "%CONSOLE_DIR%" && "%CPY%" -m neko_console"
timeout /t 8 /nobreak >nul
echo       等 8 秒；若没弹 UAC，说明已是管理员，直接开
echo.

echo [>>>] 现在切到原神，进入大世界，站在有敌人的地方。
echo       按任意键继续启动引擎（不想现在开原神就直接按）。
pause >nul
echo.

echo [3/4] 启动 Autopilot 引擎...
cd /d "%PLUGIN%"
"%PY%" -m autopilot.tools.run_loop --title 原神 --tick-rate 5
echo.
echo [X] 引擎退出了（Ctrl+C 停止）。
echo     看看 %PLUGIN%\autopilot\_runtime\engine_stderr.log 末尾。
pause
```

### 用法

```
双击 start_demo.bat
  ↓ 宿主起（12 秒）
  ↓ Console 起（弹 UAC → 点「是」）
  ↓ 提示你切到原神
  ↓ 按任意键 → 引擎起
  ↓ 另开一个窗口：python -m autopilot.tools.overlay --mode dev
```

**寻路不在这个脚本里** —— 它没有独立进程，由 Console 的「寻路」页签起
（脚本路径已修，`path_problems()` 现在是空的）。而且寻路与引擎**互斥**，
所以流程是「先停引擎 → 再在 Console 里点启动寻路」，别两个一起开。

### ⚠️ 启动顺序为什么是这个

引擎和寻路**抢同一套键鼠注入**，一方松键会打断另一方
（`pathfind.py:214-226` 的三道护栏，第 2 道就是「引擎在跑 → 拒寻路」）。
所以**演示时不要同时开寻路和引擎**。

overlay 放最后，因为它纯读文件，起早了也只是显示空数据。

## C3 · Fallback 方案（每个环节挂了怎么办）

| 挂在哪 | 现象 | 怎么办 | 还能演什么 |
|---|---|---|---|
| **UAC 不弹** | Console 直接开了 | 多半已是管理员，正常用 | 全套 |
| **Console 起不来** | 窗口一闪就没 | 看 `%CONSOLE_DIR%\console.log` 末尾 30 行；先把 `require_admin` 改 `false` 确认能起来 | 只演引擎 + 卡片（Console 不是必需的） |

| **实体检测被关** | 日志有 `ENTITY_DETECTOR_UNAVAILABLE` | 没 DirectML / 超预算。设 `NEKO_ENTITY_THRESHOLD_MS=200` 放宽 | 只能演场景判定，**演不了打怪** |
| **YUI 不说话** | 卡片在跳、宠物不吭声 | 台词映射是通的，先确认宿主在跑、模型可用 | 改演「卡片上的意图计数在跳」 |

## C4 · 演讲稿（2~3 分钟）

> 按「这是什么 → 它现在能做什么 → 有什么不一样 → 接下来」的顺序。
> 括号里是**动作提示**，不用念出来。

### 0:00 — 这是什么（20 秒）

「这是一个陪玩 AI。它做的事和你自己盯屏幕一模一样：看画面、判断发生了什么，
然后该动手就动手。区别只是它不会累，也不会走神。」

**（此时让观众看游戏画面 + 桌面上的宠物）**

### 0:20 — 它现在能做什么（60 秒）

「现在这一版，它能做到三件事：

**第一，它看得见。** 现在屏幕上有什么它就知道 —— 左边这几个小怪、右边那个
宝箱，全是它自己认出来的，不是我告诉它的。

**第二，它知道你在不在状态。** 你在正常大世界还是在开菜单，它分得清，
所以它不会在你切地图的时候乱按。

**第三，它真的会动手。** 看到怪，它自己转身就打。」

**（此时如果场景 A 成立，角色已经在自动打了 —— 这是全场最强的一帧，
务必安排在这 30 秒内发生）**

### 1:20 — 有什么不一样（40 秒）

「我想强调三点。

**第一，它不作弊。** 它只截图看画面，不读游戏内存、不改游戏文件。
市面上不少游戏 AI 是读内存的 —— 那种被封号的例子很多。这个项目从设计上
就绕开了那条路。

**第二，它不上传。** 识别、判断、操作全在你这台电脑上完成，
一张截图都不往外发。你玩什么、看到什么，只有你自己知道。

**第三，它知道什么时候闭嘴。** 这是我花的最多时间的地方 ——
早期版本一出故障能连着播报两千多次。现在同一个消息五秒内只说一次。」

### 2:00 — 接下来（30 秒）

「还差的：它现在只会『看到什么反应什么』，还不能自己规划路线。
让它从这走到那边，这件事我们正在做，但今天不能承诺。

血量和能量值也还没做 —— 因为那需要每个玩家的屏幕分辨率单独标定一次。」

### 2:30 — 收尾（15 秒）

「所以它现在不是外挂，是个**还记得你上次走到哪的朋友**。」

## 演讲时的三个纪律

1. **只说已经验证过的**。第 C0 节那张表就是边界，越过去就是在骗人。
2. **主动说不能做什么**。观众自己会去试，你不说他们也会发现 ——
   说了反而加分。
3. **别承诺时间**。「快好了」比不给日期更糟。
