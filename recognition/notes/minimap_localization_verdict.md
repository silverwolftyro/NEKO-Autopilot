> 2026-10-01　　对应规划文档 §14

## 一句话

**"游戏渲染小地图 ↔ 米游社静态底图"这一对数据源，任何外观匹配方法都定位不了。**
不是调参问题，是两个数据源之间没有可匹配的共同结构。

## 两个真实缺陷（不是本轮结论的原因，但都得修）

### 缺陷 A · 全局特征库密度账不成立

OpenCV 4.11 `BFMatcher.knnMatch` 在训练集超约 20 万描述子时断言失败（隔离复现）：

```
nf=  60000  knnMatch OK
nf= 150000  knnMatch OK
nf= 298000  knnMatch FAIL  (-215 Assertion failed)
```

密度账：L2 底图 42.5 MPix 最多挂 20 万点 = 每 213 px² 一个；
小地图 6.8 万 px² 有 1700~2443 个 = 每 28~40 px² 一个。
**差 5~7 倍，且不可修复**（要对齐需 L2 挂约 220 万点）。
→ 全局库匹配原理上不成立，**必须先有位置先验**。

### 缺陷 B · 金字塔切片时把颜色丢了

```
teyvat_P0.png            饱和像素 17.52%   p95 饱和度 83
P0_pyramid/L2_full.png   饱和像素  0.00%   BGR [28,28,28] 三通道相等
P0_pyramid/L0/*.png      饱和像素  0.00%
锚点裁块内                彩色像素 87.0%
```

`chunk_loader._read_uncached()` 与 `pyramid_loader.get_level()`
**都写死 `cv2.IMREAD_GRAYSCALE`**。灰度化把"水(青绿)/植被(深绿)/路(米色)"
这条最强语义轴抹平（彩色 BGR std [34.6, 24.8, 48.0] → 灰度 28.5）。

**但修它救不回外观匹配**：实测彩色窗口与灰度窗口内点数完全一样（3~4 vs 3~4）。

## 本轮踩到的两个自己的坑

1. **"ORB 特征数 > 400"不能当世界帧过滤器。**
   `b:f00215` 的小地图 ROI 被**加载界面角色立绘**盖住（"探索派遣奖励"），
   立绘 ORB 特征 1658 个，比真实小地图还多 → 骗过过滤器。
   **帧筛选必须用 `scene_detector` 稳定态。**

2. **RANSAC 退化解伪装成成功。**
   加过滤前三帧最强命中"完全一致"（L0=(14724,14496)，220 内点，差 0 m），
   实际**拟合尺度全是 0.00** —— 所有内点塌成一点，是水面/空地重复纹理的假聚类。
   **相似变换必须校验 `scale > 0` 且 `|rotation| < 12°`**（小地图正北朝上、缩放档固定）。
   加上后真解从 220 掉到 5~7。

### 但大地图当底图仍然失败

256×256 窗口（287 m）全图滑窗，SIFT：

| 扫描 | 查询 | 峰内点 | 峰位 |
|---|---|---|---|
| 大地图 | 枫丹廷小地图 ×5 | 253/258/243/230/219 | 全 **(433,688)** |
| 大地图 | **纳塔小地图** ×4 | 56/56/76/74 | 全 **(433,688)** |
| P0 | 枫丹廷小地图 ×5 | 165/164/156/150/145 | 全 (823,954) |
| P0 | **纳塔小地图** ×4 | 51/48/51/53 | 全 (824,955) |

**负对照和正对照落在同一像素。** 相隔数百公里的两个小地图，
峰都落在**陆水交界的拐角**上。

**根因**：水陆交界是提瓦特地图上到处都有的高频结构。
任何小地图都含水陆边界 → SIFT 必然匹配到底图上任意一条长海岸线。
**峰位由底图决定，不由查询决定 —— 这不是定位。**

### 方法论修正（重要）

上一轮我用**绝对内点数**做判据。本轮 SIFT 拿到 219~258 内点，
看起来比上一轮的 2 内点强一个量级。**加上负对照后结论不变。**

> **任何基于外观的检索，在提瓦特这种"大量重复自然结构"的地图上，
> 必须配负对照**：拿已知不同地点的查询扫同一张底图，峰位必须分开。
> 只看正对照的绝对内点数一定会被骗。

这和之前 ID3 管线 bug 是同一类错误：**没有负对照的指标 = 不知道有没有泄漏。**
