## 二、怎么点选路点（anchors_viewer.py）

### 2.1 启动

```
cd <RECOGNITION_ROOT>\exports\benchmark\scripts\misc
python anchors_viewer.py
```

### 2.2 鼠标

| 操作 | 作用 |
|---|---|
| **左键单击** | 加一个**路点**（世界坐标，e2e 会逐点走） |
| **Shift + 左键** | 加一个**命名锚点**（图像配准用，和路点是两回事） |
| **右键** | 删**离光标最近**的那个路点（不是最后一个） |
| 中键拖动 | 平移画布 |
| 滚轮 | 缩放 |

### 2.3 键盘

| 快捷键 | 作用 |
|---|---|
| **Ctrl + S** | 保存路点到 `recognition\data\user_waypoints.json` |
| **Ctrl + O** | 从该文件加载 |
| **Ctrl + C** | 复制当前路点序列到剪贴板 |

### 2.4 保存时发生什么（2026-10-08 修）

`dump_waypoints()` 现在会**自动补齐首尾**：

- `start` = 第一个路点的 (x, z)
- `target` = 最后一个路点的 (x, z)
- 只有 1 个路点 → `start` 和 `target` 都是它
- **没有路点 → 拒绝保存**（提示「先点选路点再 Ctrl+S」）
- `waypoints` 列表保留全部（不去尾）—— 最后一个点和 `target` 重复无妨

> 修之前 `start` / `target` 恒为 `null`，e2e 一读就整份拒绝
> （`✗ 路点文件不合规：target 必须是 [x, z] 两元素`）。

## 三、起点坐标从哪来

`--start-world X,Z` 是**必填**的，三种拿法：

### 3.1 从上一次的寻路汇总里抄

```
  位置 : (3567.3, 4300.0)
```

### 3.2 跑一次 `e2e_teleport.py`

它会传送并打印传送后的世界坐标。

### 3.3 从 `user_waypoints.json` 抄

保存后 `start` 字段就是点选时你站的位置。如果你就站在那儿，直接用。

> ⚠️ **不能自动猜**。脚本的原话：「不知道它会跑哪去」比多一个参数糟糕得多。

## 四、跑 live 寻路

### 4.1 完整命令

```
cd <RECOGNITION_ROOT>\exports\benchmark\scripts\misc
python e2e_pathfind.py --start-world <X,Z> --waypoints-file <RECOGNITION_ROOT>\data\user_waypoints.json --live
```

### 4.2 关键参数

| 参数 | 说明 |
|---|---|
| `--start-world X,Z` | **必填**。开跑时你站的世界坐标 |
| `--waypoints-file F.json` | 路点文件；与 `--target-world` / `--walk-forward` / `--target-tp` **互斥** |
| `--live` | 真发按键。**必须是管理员**（游戏内核级反作弊 → UIPI 隔离永久存在） |
| `--delay N` | 启动前倒数 N 秒，等你切回游戏。**默认 8** |
| `--seconds N` | 运行时长上限，默认 60 |
| `--arrive R` | 到达阈值（米），默认 5 |
| `--sprint` / `--walk` | **默认就是 Shift+W 跑步**（`sprint=True`）；加 `--walk` 才降速为走路 |
| **`--i-know-start`** | 起点体检的逃生门（见 §5）。默认 False |

### 4.3 不加 `--live` 会怎样

dry-run **仍然需要游戏窗口**（要抓屏定位），但不发任何按键。
站在没开游戏的机器上会直接报：

```
✗ 找不到窗口 '原神'：WindowNotFoundError
```

## 五、起点体检（2026-10-08 新增，仅 `--waypoints-file` 模式生效）

相位相关是**相对**定位 —— **起点给错它照样收敛、照样 arrive，只是到了一个错的地方，全程零报错**。所以起点错了必须在脚本里拦。

| 差值 | 行为 |
|---|---|
| ≤ 500m | 只提示（点选后挪动位置是正常的） |
| 500m ~ 2000m | 醒目警告（`!!!!` 框），**继续跑** |
| **> 2000m** | **拒绝启动**（exit 2），除非加 `--i-know-start` |

实跑样例：

```
  !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
  !! 起点体检未通过：路点文件里的 start 与本次 --start-world 相距 2366m
  !!   文件里的 start = (2176.3, -1053.1)   （点选路点时你站的位置）
  !!   本次 --start-world = (1000.0, 1000.0)   （这次开跑时你站的位置）
  !! 差 2366m > 2000m —— **这已经不是'挪了挪'，是换了一张地图的量级**。
  !! 继续跑的结果：相位相关照样收敛、照样 arrive，但到的是**错的地方**，而且不会有任何报错。
  !! 确认你知道自己在干什么，就加 --i-know-start 继续；
  !! 否则请改 --start-world，或重开 anchors_viewer Ctrl+S 重存路点。
  !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
  ✗ 已拒绝启动（缺 --i-know-start）。
```

## 六、常见错误

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `✗ 路点文件不合规：target 必须是 [x, z] 两元素` | 老格式文件（`target: null`） | 现在已降级兼容；重开 anchors_viewer `Ctrl+S` 会自动补齐 |
| `✗ 路点文件 schema_version=N，本脚本只认 1` | 版本漂移 | 用 anchors_viewer 重存一次 |
| `✗ 路点文件不合规：第 2 个路点坐标不是有限数` | 坐标是 NaN / 字符串 | 重新点选 |
| `起点体检未通过` | 点选时和开跑时不在同一片区域 | 改 `--start-world`，或重存路点 |
| `⚠ 直线距离 XXXXm > 300m` | 单段太远 | **建议拆成多路点**，别硬跑直线 |
| `⚠ 距离已到但朝向差 XX° > 30°，先转正` | 到了但没对准 | 正常，会自动转正后重判 |
| 路点跨海 / 跨山 | 点的时候没看地形 | 重选。相位相关只管位移，不管可通行性 |
| 角色原地打转 | 大角度转向期（旧机制） | 已改「站定转」，见全景总结第十章 |
| `[STAND-SEG]` 显示达成率低 | 拆段被游戏裁掉 | 已在排查，见 `[TURN-SPLIT]` 汇总 |
