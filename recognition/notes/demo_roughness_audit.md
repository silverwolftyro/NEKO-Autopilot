# Demo 出厂前粗糙度审计

> 2026-10-16 ｜ 面向「观众能感知」的粗糙点
> 证据：`_runtime/` 真实事件流（50 个 run）+ `event_to_yui.py` + `layout.py` + `start_demo.bat`
> **只读，未改任何代码，未开原神。** 不列开发者级问题。

---

## 判定标准

| 级 | 含义 |
|---|---|
| **A** | 观众会当场出声问「这是坏了吗？」 |
| **B** | 观众会注意到，但还能忍 |

---

# 一 · A 级（出厂前必须处理）

## A1 · YUI 在故障时 5 秒复读同一句 —— 卡带感最强 🔴

**证据**（真实 run，按 `SKIP_CODES` + 5 秒节流模拟 YUI 实际输出）：

| run | 时长 | YUI 会说 | 同一句重复次数 |
|---|---:|---|---:|
| `20261010_225316` | 207 s | 43 句 | **「画面有点看不清，先停一下」× 39** |
| `20261011_180732` | 155 s | 34 句 | **「这个动作我没敢做」× 31** |

即：**每 5.1 秒重复同一句，连续 3.5 分钟。**

模块 docstring 写着「不节流的话 YUI 会像卡带一样把同一句话重复十几遍」——
**节流只是把「十几遍」变成「每 5 秒一遍」，问题没解决，只是变慢了。**

| 项 | 值 |
|---|---|
| 改法 | 给 `PERCEPTION_DOWN` / `INTENT_REJECTED` 加「同一句最多说 N 次」上限，或直接进 `SKIP_CODES` |
| 成本 | **分钟级** |
| 不改观众会想 | 「这破 AI 卡死了」「语音模块坏了」 |

---

## A2 · 说出「有怪！0个，小心点」

**证据**：`20261014_215401` 真机 run，`ENEMY_DETECTED` 触发 6 次，count 依次为
**`0 → 2 → 1 → 1 → 1 → 0`**。count=0 时台词照样播：

> 有怪！0个，小心点
> ……
> 有怪！0个，小心点

（`{count}` 占位符本身替换正常，问题是**逻辑上 0 就不该播**。）

| 项 | 值 |
|---|---|
| 改法 | `count <= 0` 时改说「怪好像没了」或不播 |
| 成本 | **分钟级** |
| 不改观众会想 | 「这 AI 连数数都不会」—— 而且是**唯一的亮点台词**，重复播两次伤害翻倍 |

---

## A3 · 说出「场景换成了UNKNOWN」

**证据**：同一 run 结尾 `SCENE_CHANGED {"from":"WORLD","to":"UNKNOWN"}` →

> 场景换成了UNKNOWN

`UNKNOWN` 是内部枚举，原样播给观众了。

| 项 | 值 |
|---|---|
| 改法 | 映射 `WORLD→大世界` / `UNKNOWN→别的地方`，或不播该 code |
| 成本 | **分钟级** |
| 不改观众会想 | 「是不是还没做完」「漏了个东西没替换」 |

---

## A4 · 开场两句连击：「启动了」+「引擎起来了」

**证据**：`CORE_STARTED` 与 `RUN_STARTED` 在 **t=0.00s 同时**触发（两个不同 code，
节流按 code 记，压不住互相）。

> 引擎起来了
> 启动了

两个 run 均如此。两句都是「刚启动」，观众只会听到一句。

| 项 | 值 |
|---|---|
| 改法 | 二选一，另一个进 `SKIP_CODES` |
| 成本 | **分钟级** |
| 不改观众会想 | 「重复了 / 口吃」 |

---

## A5 · 攻击完全没有门控：前 22 秒对着空气猛打 🔴

**证据**（`20261014_215401`，规则是 `world_attack_only_with_enemy`）：

| 时刻 | 已检测到敌人数 | 期间按键次数 |
|---|---:|---:|
| t=0 ~ 22.2 s | **从未检测到任何敌人** | **100 次** |
| t=22.2 ~ 28.5 s | 0 | 30 次 |
| t=61.2 s ~ 结束 | 0 | **70 次** |

**355 次攻击全部 outcome=OK，但敌人计数多次为 0。**
唯一启用的规则叫「世界场景且有敌人才普攻」，实际表现像**无条件连点**。

| 项 | 值 |
|---|---|
| 改法 | 查 `has_enemy` 信号链（大概率与 ENEMY_DETECTED 的 `count` 不同源） |
| 成本 | **小时级** |
| 不改观众会想 | **「这是按脚本刷出来的吧」** —— 这是全片最伤可信度的一点 |

---

## A6 · demo 最后一帧是橙色的「已停止」+「场景: UNKNOWN」

**证据**：真实快照 `state:"STOPPED"`, `scene:"UNKNOWN"`, `capture.active:""`,
`session_state.active:false`。按 `build_panel` 渲染：

```
● 无会话 · 已停止   4.8 Hz   223ms P95      ← 橙色（ACCENT_WARN）
场景: UNKNOWN
意图: 355 次
通道: —
急停: F12
```

`state=STOPPED` 在配色表里本应是红色，被 `无会话` 的橙色覆盖——
**观众看到的是橙字「已停止」+「UNKNOWN」+「通道: —」**。

| 项 | 值 |
|---|---|
| 改法 | 正常结束时把 state 显示成「已完成」并转绿；或 demo 结束前 3 秒就停，别停在 STOPPED 帧 |
| 成本 | **分钟级** |
| 不改观众会想 | **「演示崩了」** —— 而这恰恰是留在观众视网膜上的最后一帧 |

# 二 · B 级（能忍，但值得改）

## B1 · 4.62 次/秒的连击节奏

355 次 / 76.8 s，均值 0.217 s、中位数 0.203 s、**标准差仅 0.089 s**。
分布是**均匀机器连击**，不是「忽快忽慢」。观众看到的是长按式狂点，缺呼吸感。

成本：**小时级**（humanizer 加节奏抖动）。不改观众会想：「手速好快」—— 中性，但不够像人。

## B2 · overlay 上 3 个只有开发者看得懂的字段

| 字段 | 观众看到 | 问题 |
|---|---|---|
| `4.8 Hz` / `223ms P95` | 第一行 | 帧率与延迟，观众无参照系 |
| `规则: 16 条（目录: …）` | 启动 banner | 暴露内部结构 |
| `意图: 355 次` | 第三行 | 计数器，非状态 |

成本：**分钟级**（删或折叠成 tooltip）。不改观众会想：盯着数字走神。

## B3 · demo bat 收尾用 `[X]` 报错符号

```bat
echo [X] engine exited ^(Ctrl+C to stop^).
```
demo **正常结束**时打的是 `[X]`（失败符号）。同一文件里 `[X]` 也用于真错误（找不到 python），
**观众无法区分正常结束和出错**。

成本：**分钟级**。不改观众会想：「最后报错了」。

## B4 · 启动脚本全英文，且提示语带「or type n to skip」

```bat
echo       Stand somewhere with 1-3 enemies in view.
set /p "GO=Press Enter to start the engine (or type n to skip) ... "
```
对接人若不懂英文，会**卡在这个提示上不知道按什么**。`(or type n to skip)` 是
给作者自己留的后门，不该出现在观众面前。

成本：**分钟级**。不改观众会想：「我不会用」。

## B5 · 12 秒 / 8 秒盲等，且没有「系统就绪」信号

`timeout /t 12` + `timeout /t 8` 是固定睡眠，不检查进程是否真的起来。
**全程没有一个「一切就绪，可以开始了」的明确提示**。

成本：**小时级**（改成轮询就绪文件）。不改观众会想：干等，不知道该干嘛。

## B6 · overlay 不由启动脚本拉起

`start_demo.bat` 第 6 行自述：*Overlay is started separately*。
即观众看到 overlay 卡片需要额外手动操作。

成本：**分钟级**。不改观众会想：少了一块本来该有的界面。

# 三 · 建议必做 Top 5（按「成本低 + 影响大」排序）

| # | 项 | 成本 | 收益 | 理由 |
|---:|---|---|---|---|
| **1** | **A6** 结束帧改成绿色「已完成」 | 分钟 | 🔥🔥🔥 | 最后一帧 = 最后印象。现在是「橙字已停止 + UNKNOWN」 |
| **2** | **A1** 同句重复上限 | 分钟 | 🔥🔥🔥 | 把 3.5 分钟 ×39 遍卡带压成最多 2 遍 |
| **3** | **A2** `count=0` 不播「有怪」 | 分钟 | 🔥🔥 | 消除「有怪！0个」这种一听就出戏的句子 |
| **4** | **A4 + A3** 去重复开场 + 过滤 `UNKNOWN` | 分钟 | 🔥🔥 | 开场不口吃、结尾不念枚举 |
| **5** | **B3 + B4** bat 收尾换符号 + 提示改中文 | 分钟 | 🔥 | 消除「最后报错了」和「我不会用」 |

**这 5 项全部是分钟级改动，加起来不到一小时，且互不冲突。**

# 四 · 我的建议：现在改 vs 留到 demo 后

## 现在改（demo 前，合计 < 1 小时）

- **A1 / A2 / A4 / A6 / B3 / B4** —— 全部是「改一句话 / 改一个符号」级别。
  它们占观众负面印象的一大半，成本却极低，**性价比不对等**。

## 认真考虑现在改（半天）

- **A5 攻击门控** —— 这是**唯一影响技术可信度**的问题。其他都是观感问题，
  只有这一个会让懂行的对接人判定「这不是 AI，是个按键脚本」。
  如果 demo 的核心卖点是「会判断」，那必须解决；如果卖点是「跑通了」，可以先讲清楚。

## 留到 demo 后

- **B1 连击节奏**、**B2 overlay 字段精简**、**B5 就绪信号**、**B6 overlay 拉起**
  —— 这四项需要改执行层或启动架构，**都会引入新的回归风险**。
  在 demo 前动它们，等于拿「一定不出事」换「稍微好看点」，不划算。

---

## 五 · 一句话结论

**YUI 的问题不是「词不够好」，是「会复读」—— 39 遍同一句话是全片最刺耳的粗糙点，
而修它只要几分钟；真正需要工程时间的只有 A5「无门控连打」那一条。**
