## 2. 判定树形式

```
if hp_bar__edge_density <= 0.1177:
        非大世界
else:
        if hp_bar__mean_s <= 104.3326:
                非大世界
        else:
                大世界
```

**物理意义**：血条在大世界里一定有内容（Lv 数字、数值文字、边框、色块），
所以**边缘密度高**且**有彩色**；菜单里那一块是空的或纯灰，
**边缘密度低、饱和度低**。

阈值来自 229 帧用户标注的手工核对，属**标定值**。

---

## 3. 误判帧与根因

| 帧号 | 真实 | 预测 | edge_density | mean_s |
|---|---|---|---|---|
| `a:f00071` | 大世界 | 非大世界 | **0.0000** | 27.68 |
| `a:f00079` | 大世界 | 非大世界 | **0.0000** | 34.50 |
| `a:f00083` | 大世界 | 非大世界 | 0.0380 | 38.84 |
| `b:f00108` | 大地图 | 非大世界 | 0.1560 | **104.33** |

### 根因

**前 3 帧是同一个病：HUD 淡出态。**

冲刺 / 交互时原神会临时隐藏 HUD，血条那块变成全黑，
`edge_density` 掉到 0，规则必然判成非大世界。

**根本原因是判定树只有一个特征源（血条）。** 单点故障。

**第 4 帧是阈值贴边**：`mean_s = 104.33` 与阈值 `104.3326` 只差 **0.0026**，
浮点误差就足以掉到错误一侧。

## 4. 试过但**没有改善**的方案（记账，避免重复劳动）

| 加了什么 | 结果 |
|---|---|
| `avatar` ROI（派蒙头像） | 5-fold 0.9544，**比旧的 0.9726 差** |
| `paimon_panel` ROI（派蒙主面板） | 同上 |
| `paimon_panel__ncc_vs_menu`（派蒙静止度） | **ID3 根本没选中它** |

**为什么派蒙静止度没用**：它的语义是「这一帧像不像派蒙菜单」。

| | paimon_panel NCC |
|---|---|
| 派蒙界面 | ≈ 1.00 |
| 背包 / 大地图 / 加载 / 祈愿 / 角色养成 | 低 |
| **大世界** | **低**（世界画面同样在变） |

**它能分开的是「派蒙 vs 其它」，不是「大世界 vs 非大世界」。**
对二分类任务没有根节点增益，所以 ID3 跳过。

## 5. 未来改进方向

### 主方向 · 时序去抖（架构层，不是特征层）

```
连续 N 帧判"非大世界" 才真正切换状态
单帧误判不触发切换
```

**这是唯一能同时解决两个误判根因的办法**：
HUD 淡出是**连续多帧**的，阈值贴边是**浮点抖动**，
两者都会被"连续 N 帧"过滤掉。

规划文档 §4.3 已定的去抖参数 N=3 秒可直接复用。

### 备选 · 多特征 OR 表决

规划文档 §4.2 原本设计的是「3 特征多数票」。当前只有 1 个特征。
补上 `minimap` 或 `party_bar` 的存在性检测，再做多数票，
可以绕开单点故障——但会引入"某个特征在大地图里也存在"这类新误判，
**需要先量化再上**。

---

## 6. 风险方向

**目前所有已知误判都是"大世界 → 非大世界"，落在安全方向。**

| 方向 | 后果 | 当前误判数 |
|---|---|---|
| 大世界 → 非大世界 | 误判成菜单 = 暂停操作 = 顶多多等两秒 | **3** |
| 非大世界 → 大世界 | **会乱按键鼠** | **0** ✅ |

这个不对称是当前方案能"先冻结"的前提。
**引入新特征时必须保持这个不对称**，否则风险等级完全不同。
