# 传送位置更新契约

> 状态：三段式状态机　　定义日期：2026-10-01
> 位置：Autopilot 感知层 / 定位层

---

## 1. 原始需求（用户原话，不改写）

> 从大地图切换成小地图的时候，如果 OCR 检测到他选择了传送锚点，
> 那就应该针对这个传送锚点进行位置更新，过程需要经历严格的选择，
> 传送锚点或者神像，经历中间态加载，然后进入大世界状态才能被认为
> 是通过传送切换位置，并且更新位置。
> 选择目标地点，传送经历加载状态，大世界重新恢复经历了这三个硬性
> 步骤，会刷新位置状态，而且直接对原来的位置状态进行抛弃。

---

## 2. 契约形式

```
[ 大世界 / 任意 ] 
      │
      │  ① SELECT —— 玩家在界面上选定了一个具体目标
      │             （传送锚点 或 七天神像）
      │             判据：OCR 读到目标名，且在候选表中命中唯一项
      ▼
[ SELECT 完成 ]  ─── 记录 candidate = (name, world_pos, region)
      │
      │  ② LOADING —— 界面进入传送过场
      │             判据：非大世界 UI 持续 ≥ N 秒
      ▼
[ LOADING 完成 ]
      │
      │  ③ WORLD_RESTORED —— 大世界 UI 恢复
      │             判据：场景检测器切回 is_world = True
      ▼
[ WORLD_RESTORED 完成 ]  →  位置刷新
```

**三段全过才刷新。任意一段断，整个事务作废。**

---

## 3. 三段的判据

| 段 | 名称 | 谁负责 | 进入判据 | 说明 |
|---|---|---|---|---|
| ① | **SELECT** | 传送 OCR 模块 | OCR 读到主标题+副标题，**在候选表中唯一命中** | 模糊/多候选都算失败 |
| ② | **LOADING** | 场景检测器 | `is_world == False` 持续 ≥ **N=3.0 秒** | 复用去抖参数，不另设 |
| ③ | **WORLD_RESTORED** | 场景检测器 | `is_world == True` 且 `changed == True` | 必须由**状态切换**触发，不是"本来就true" |

### 为什么必须区分"切换"和"本来就是 true"

如果传送过场结束后回到大世界，但检测器**一直**认为是大世界（比如过场
太短没触发去抖），那说明**我们根本没观察到这次传送**。
此时若刷新位置，就是拿一个未经证实的假设覆盖真实位置 —— 比不刷新更危险。

所以 ③ 的判据是 `changed == True`，**不是** `is_world == True`。

---

## 4. 刷新 = 替换，不是更新

```
position := candidate.world_pos          ← 直接覆盖
position_source := "teleport"            ← 记录来源
position_confidence := 1.0               ← 传送是硬事实，无不确定性
previous_position := 旧值                ← 仅供日志/调试，不参与计算
```

**不做加权、不做平滑、不做卡尔曼融合。**

理由：传送是**位置的一次硬重置**。旧位置和新位置之间没有连续性，
任何形式的"融合"都是在拿两个不相关的估计互相污染。

传送后的第一次小地图定位**从 `candidate` 起步**，而不是从旧位置起步
——这正是"抛弃原位置"的实际含义。

---

## 5. 作废条件

以下任一情况发生，**本次传送事务作废，不刷新位置**：

| # | 情况 | 判据 |
|---|---|---|
| 1 | ① 未唯一命中 | OCR 读到多个候选，或编辑距离超阈值 |
| 2 | ① 之后 ② 始终没来 | 长时间仍是 `is_world == True`（玩家取消/对话打断） |
| 3 | ② 之后 ③ 没来 | 加载中掉线、切场景、长时间不恢复 |
| 4 | ③ 之后位置自相矛盾 | 传送后小地图定位结果与 `candidate` 偏差 > 30 米 |
| 5 | 事务超时 | ① 到 ③ 全程超过 **T_max = 30 秒** |

**作废后 `position` 保持不变，`position_source` 不变。**
宁可继续用旧位置，也不要写一个半途而废的状态。

---

## 6. 接口

**这是小地图定位模块与传送 OCR 模块之间的契约。**

```
传送 OCR 模块                          定位层
     │                                  │
     │  select_target(name)             │
     │    -> SELECT | None              │
     │                                  │
     │  on_scene_state_changed(...)     │
     │    (is_world: bool)              │
     │                                  │
     └──────► 事务状态机 ◄──────────────┘
                  │
                  ├─ ①+②+③ 全过 →  position = candidate
                  └─ 任一失败    →  position 不变
```

### 状态机需要什么

| 输入 | 来源 |
|---|---|
| `candidate` | 传送 OCR 唯一命中的那条记录 |
| `is_world` | 场景检测器 `SceneDetector.update()` 的 `is_world` |
| `changed` | 同上，`changed == True` 表示**这一步**刚切换 |
| `timestamp` | 调用方提供（秒级，单调不减） |

### 状态机输出什么

| 输出 | 含义 |
|---|---|
| `position_refreshed: bool` | 这一步是否真的刷新了位置 |
| `position` | 刷新后的世界坐标 |
| `position_source: "teleport"` | 刷新时的来源标记 |

**注意方向性**：`position_source` 让上游能区分
"这次位置是小地图定位算出来的"和"这次位置是传送直接给的"。
后者精度高得多，值得区别对待。

## 7. 已知未决

- ❓ **传送落点 vs 落地区分**：`tp.json` 有 `position`（本体）和
  `tranPosition`（落点）两个坐标，两者差 7.54 米（均值）。
  **契约里 `candidate.world_pos` 该取哪个尚未拍板。**
  倾向取 `tranPosition`（传送后角色实际站的位置），但需要实机验证。
- ❓ **N=3.0 秒是否够**：传送过场有多长？需要实机测。
  若过场短于 3 秒，② 不会触发，事务作废 —— 这是**保守失败**，
  宁可漏刷不可错刷，但会损失功能。
- ❓ **④ 的 30 米阈值**：拍脑袋定的，需要实测分布。

## 7. 时序去抖标定结果 ✅

> 标定日期：2026-10-01　　数据：`session_a` 1512 帧 / 151.2 秒 / 10 fps

### 结论：N=3.0 秒 / M=1.0 秒 已实测确认

| 项 | 值 |
|---|---|
| 录制内容 | 12 段操作、11 次状态切换 |
| N/M 扫描 | 15 组参数**全部得到 11 次切换**（与真实操作次数一致） |
| 最短真实大世界段 | **1.9 秒** |
| 最短真实非世界段 | **8.6 秒**（t=65.6~74.1，退出大地图的过渡态） |
| 采纳值 | **N=3.0s / M=1.0s** |

### 选值依据

* **N=3.0s** —— 最短非世界段 8.6s，有 2.8 倍余量。该段内含
  **2 个 0.2 秒的 raw 抖动**，去抖后合并成完整一段，**切换次数
  仍是 11**（无多余切换）
* **M=1.0s** —— 最短大世界段 1.9s，1.0s 抓得到；0.4 秒以下的
  抖动被滤掉

### ② LOADING 段是否够长

契约 §5 提到「N=3.0 秒是否够」是未决项。**现在有答案了**：

* 本次录屏里**最短的非世界段是 8.6 秒**，远大于 N=3.0s
* 意味着 ② 段**不会因为过场太短而漏触发**
* ⚠️ 但这**只覆盖了本次录屏的操作类型**。若存在
  "开背包 0.8 秒就关掉"这类操作，② 不会触发，事务作废
  —— 这是**保守失败**（宁可漏刷不可错刷），代价是丢功能
