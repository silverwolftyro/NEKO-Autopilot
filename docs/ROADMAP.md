## 中期（1 个月）

### 5. 寻路做成闭环 `[~]`

现在是**离线**生成 `move_to` 意图——人给路线，程序给意图。
闭环缺的是执行侧。

- [ ] 执行器：意图 → 小步位移 → 重新定位 → 纠偏（**已有骨架，未接完**）
- [ ] 卡住检测与两级脱困（爬升时冲刺下坠+后退，参考 BetterGI 的公开设计思路）
- [ ] 全程 `--live` 真机长跑：**≥ 2 小时无人工干预**才算过
- [ ] 传送点自动寻路：识别当前位置 → 选最近锚点 → 走过去 → 传送到目标

> ⚠️ 这里的门槛是"真机长跑"，不是"测试通过"。
> 已经证伪过 50 条路线，其中不少就是"测试全绿但真机跑不通"。

### 6. 规则引擎的表达力 `[ ]`

现在的规则是"信号 → 意图"的单层映射。真实策略需要：

- [ ] 状态机：带超时和转移守卫的显式状态
- [ ] 时序表达式：`A 之后 3 秒内出现 B`
- [ ] 计数器与阈值：`连续 5 帧置信度 > 0.8`
- [ ] 规则热加载：改 TOML 不重启引擎
- [ ] **规则回放**：用录制的状态流重放，验证规则改动没退化
      （现在改规则只能靠人盯屏幕）

### 7. 多游戏 `[ ]`

## 明确**不做**的

写下来是为了避免反复讨论：

- **不**做绕过反作弊的方案（内存读写、驱动注入、封包）。
  当前路线只走屏幕像素 + 模拟输入。这既是技术选择，也是底线。
- **不**承诺适配任何游戏。要接就自己接，我们提供框架和文档。
- **不**做闭源核心 + 开源外壳的分层授权。
- **不**把 GPL 资产打进包。需要就用自己的（见 [GPL_BOUNDARY](GPL_BOUNDARY.md)）。

## 怎么参与

按性价比排：

1. **报一个你实际遇到的问题**，附上 `check_env` 输出 → 最有价值
2. **跑一次测试并把失败贴出来** → 我们大概率会修
3. **补 GIF / 录屏** → 上面那条是当前最缺的东西
4. **接一个新游戏** → 顺便帮我们验证抽象对不对
5. **读 `recognition/notes/` 里那 50 条证伪路线** →
   如果你也在同一条路上撞过墙，那里面可能有你要的答案
